# Post-bab9907 experiments — withdrawn on 2026-10-20

HISTORICAL / INACTIVE. The user requested exact restoration of all tracked files
to bab9907. The critical-visual implementation ff6d2b7, necessity implementation
9488498 and subsequent uncommitted selection-review edits are withdrawn, rather
than disabled by settings. This document preserves their full former capacity
report sections. It does not describe the active pipeline and must not be used
to reintroduce either mechanism without new user authorization. Original commits,
Campaign/Batch data and generated artifacts remain historical evidence.

## Editorial necessity and I13 capacity diagnosis (2026-10-20)

This supersedes v1's promotion of every visible optional prerequisite and
unrestricted required/useful annotations. Selection is `editorial_selection_v2`;
Critic is 4.3.8 with the distinct `academic_poster_multifamily_v12_necessity`
rubric (information/narrative 1.6.0, layout-family 1.3.0). The 78-point gate,
weights, scientific verification and critical_visuals_v1 remain unchanged.
Historical scores, frozen foundations and Campaign artifacts are immutable.

Scientific validity/usefulness is separate from display necessity. Planner and
Curator's existing calls distinguish indispensable explanations/conditions from
useful reserve, without a mandatory ratio, sentence limit or module quota.
`required/useful` and other unsupported necessity reasons trigger a structural
review; a genuinely all-required short board remains legal. A measured initial
fast-capacity failure can also request review of an otherwise valid contract.
No automatic reason-based downgrade or independent scientific/association judge
is introduced.

`src/layout/selection_review.py` runs at most one internal ID-only review per
global iteration, using the existing GroundedContentOptimizer model helper.
It charges before the call and shares the existing four-global/two-family
budget and one quality reserve. Durable purpose charges survive family retries
and process restarts. Disabled content optimization (including loop overrides),
strict Validate and exact-parent fallback cannot edit selection. Required visual
input/ownership failures take their own route before a review spends budget.
The response must cover the current visible IDs exactly; no scientific prose,
new evidence, ownership changes or visual decisions are accepted. A demotion
must name retained required anchors in its actual current module. Planner
requirements, explicit pins, important research phases and deliberate omissions
remain protected. Same-root bank variants cannot erase required/omitted status;
a reviewed decision applies to that root's metadata without changing bank text.

A specific condition records `required_for_claim_ids`. Optional findings no
longer globally promote their prerequisites forever; selected findings still
carry all context edges. Curator recovers only unconditional requirements and
context reached from actually selected claims, so unused optional findings do
not create condition-only source modules. Whole-board exact, Preflight and Critic
checks reject missing prerequisites and orphan scoped conditions, including verified variants.
After existing source-aware auxiliary attribution, merged protection is
recomputed from current necessity. No source/dataset detail becomes required
merely because it entered Methods or Results. Existing source ownership remains
a prerequisite for review, not something the review invents.

A resolved review refits the same attempt's own board and returns to the existing
compaction, completion, whitespace, typography, geometry, reading and artifact
guards. A shared unresolved selection stops once with
`shared_editorial_selection_unresolved`, without excluding a family, calling
Critic, committing a Batch iteration, or publishing rejection/design knowledge.
A concurrent graceful stop still pauses. Genuine physical/reading/capacity
failures retain bounded repair/retry; programming errors keep their own route.
Diagnostics save the input-board digest, attempt identity and adopted ID contract;
the original layout input is never overwritten or borrowed from another round.
All twelve and future shared-interface families inherit this path. Classic stays
three unsplit/unspanned regions; standalone classic keeps its legacy behavior.
Locked v1 artifacts retain their old reason vocabulary but not an exemption from
actual required-information loss. New Batches/authorized resumes record v2;
unknown frozen policies and replay policy drift fail closed.

## Critical scientific visual retention (2026-10-19)

This supersedes optional-only key-visual placement and omission-as-metadata
behavior. The loop uses `critical_visuals_v1`, Critic 4.3.7 and the distinct
`academic_poster_multifamily_v11_visuals` rubric (visual_assets/visual 1.1.0).
Other scientific/editorial/reading/composition versions, overall weights and the
78-point gate remain unchanged. Historical artifacts/scores remain immutable.

`src/layout/visual_requirements.py` defines a paper-scoped ID-only contract for
all extracted figures/tables. The existing Planner/Curator calls review their
necessity with evidence and original source-section pointers. Multiple critical
method/result/comparison visuals are supported; Planner requirements and a valid
original key visual are mandatory floors. Unclassified decisions, unknown keys,
missing/changed/unreadable required files and ambiguous missing owners fail
closed. Asset IDs, caption hashes, source identity and original resource hashes
bind the decisions. New scientific prose, inferred replacement-equivalence,
foreign boards and arbitrary ownership guesses are not accepted.

A resolved contract survives family retries without sharing another attempt's
prose. Only completed Campaign iteration snapshots publish it; resume scans
committed snapshots and rejects conflicts, disappearance or source drift.
Lineage snapshots exclude the canonical field. Old foundations remain frozen;
old Campaigns can establish an overlay in an authorized Curator exploration.
Batch resume records the visual policy/settings; unknown versions/settings drift
fail. Replay inputs bind policy, source resources and measurement configuration.
Development itself never resumes a Batch or adds a model round.

Required assets enter initial selection. Required subsets retain all mandatory
IDs together, and their owner cannot be skipped. Optional text/assets can yield
within existing bounded search; a missing-image text-only fit cannot become the
whitespace baseline. Subsequent completion/repair/recovery and destructive
revision checks preserve the contract. Scoped duplicate removal may remove extra
occurrences but never the last required copy. Required raster geometry caps
magnification at the existing DPI floor, using original pixel aspect, in both
measurement and compilation. Size floors are conservative configurable checks,
not a guarantee of axis/legend legibility. All twelve families and future shared
registrations inherit the path; classic remains exactly three unsplit/unspanned
regions. Strict Validate/exact fallback keep locks; standalone classic retains
legacy content/layout behavior.

`src/layout/render_visuals.py` checks actual named PPTX image embeddings against
source hashes, exactly-one placement, crop, geometry, bounds, aspect and DPI. It
reuses the existing RenderFit PDF export to confirm painted image positions and
rejects later opaque rectangular covers. Evidence binds candidate, contract and
current PPTX/PNG hashes. Missing/unavailable/stale proof cannot certify a
required visual. The existing vision Critic must explicitly return one readable
assessment per required ID; missing/unreadable/uncertain assessments are critical
regardless of a high score. This does not add a withdrawn image/module semantic
association judge or extra source-image model calls. Truly reviewed image-free
papers receive N/A for asset aesthetics/provenance instead of an automatic 100;
only this explicit N/A source is excluded from the source denominator. Missing
evaluators still contribute zero.

Shared unresolved visual input/ownership stops once with
`shared_visual_requirements_unresolved`; unavailable technical render proof
stops with `critical_visual_render_unconfirmed`. Neither poisons the family pool,
calls Critic, spends a committed iteration or publishes rejection/knowledge.
Concurrent graceful stop still pauses. Family capacity/exact/physical failures
retain their bounded recovery. Unknown programming failures retain their own
exception route. Diagnostics include the contract, preflight visual report and
render visual report; optional restoration now exposes individual content and
whitespace rejection reasons without weakening either guard.
