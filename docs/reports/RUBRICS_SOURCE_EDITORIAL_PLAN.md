# Rubrics 原章节驱动正文与家族感知编辑方案

状态：方案已实施，代码与离线验收完成。修订二：2026-10-27（北京时间）。
本版取代上一版第十三节的硬编码物理阅读路线/前置排序提案；历史审计事实不变。
实施基线为 db43de5 / explore_samples_v9。新默认主链为 explore_samples_v10 / sample_source_science_v1；完整CPU回归1077项及5子测试通过，另补缓存隔离用例所在文件10项通过。本文不表示真实模型科学、正文质量或审美验收已完成。

## 一、目标与范围

将当前 Rubrics 独立样本的正文生产方式改为原始 PosterGen 的编辑模式：
根据连续论文章节和研究故事联合组织正文、模块与图表；获得实际排版后，
再结合原章节补写、压缩、拆并和重组。适配全部15个平等布局家族及其合法变体。

从 Rubrics 主链彻底移除 EvidenceBuilder，包括调用、原子事实白名单以及
对 evidence_bank/ev_... 的必需依赖。不能通过重命名、补空证据库或在后台
重新预提取一份原子事实库保留同样限制。科学支持记录在正文生成后建立。

取消Rubrics按原文/角色顺序强制排序、重排和拒绝布局的机制。自然阅读路线交由
现有Balancer中的视觉模型判断：从上往下与从左往右平级，基于实际分组、跨栏、
镜像和视觉层级判断。保留确定性的物理合法性和原文科学一致性检查。

保留每样本独立写作、覆盖优先且不看历史分数的家族选择、有限预算、确定性
坐标编译、科学与物理检查、PNG/可编辑PPTX、所有结果保存和检查模板。
不实现未来 Rubrics/Harness，不引入跨样本正文/模板检索或分数筛选。
独立 classic 路径保持现有行为；共享 EvidenceBuilder 文件若仍被 classic 使用，
保留给 classic，不在 Rubrics 导入或执行它。

## 二、目标流程与调用边界

共享论文基础：PDF -> Parser -> 原文、章节/段落/表格索引、原始图表及元数据。
共享的是原始材料，不共享任何样本的故事、正文、选择或核验结论。

每个独立样本：
1. SourceNarrativePlanner 根据连续原章节形成研究主线、读者问题和少量必须保留的
   科学含义。原文位置仅作来源记录，不预写固定模块，不建立允许写作事实全集。
2. 按现有覆盖优先策略冻结一个家族。家族契约和有界合法几何候选提供区域尺寸、
   内容角色和分割/跨栏/镜像能力，不指定唯一正确的阅读路线，不声称草稿已可行。
3. SourceCurator 一次联合生成动态数量模块、完整正文、主支撑层级、图表及组织意图。
   模型以整篇故事和原章节写作，取代先筛原子证据再逐条组装正文的方式。
4. 求解器在有限合法变体池中拟合草稿；已有可显示候选时，用共享测量/编译/渲染能力
   生成独立草稿预览。核验前草稿与预览仅供诊断，不是正式海报或已核验科学输出。
5. FamilySourceBalancer 在既有有界轮次接收整稿、连续原章节、实际几何、测量与预览。
   先判断实际自然阅读路线及歧义，再提出必要的正文/结构/合法布局修改；可以不改。
   没有物理候选时仅做拟合诊断，不能声称已完成视觉阅读判断。
6. SourceVerifier 对准备采用的完整候选直接核验原文支持、必要含义及解释上下文。
   拟合/编辑/核验形成同一个有限循环；科学无效草稿不得当作有效基线。
7. 保留的一次quality机会审看当时最完整候选的实际预览，并允许有来源的内容完善和
   阅读改进。所有改稿重走科学核验和实际拟合；不存在额外免费阅读裁判循环。
8. 最终正文、上下文、来源证明和几何一致后冻结。预览阅读结论只绑定其实际输入，
   修改后不能自动继承“清楚”的结论；未复查状态明确记录。
9. 安装冻结候选 -> 样式 -> 确定性编译 -> Preflight -> Renderer -> RenderFit
   -> 既有Critic对最终PNG独立判断自然阅读 -> 全分数保存及独立检查模板。

SourceNarrativePlanner 和 SourceCurator 取代现有证据驱动Planner、模块Curator、Writer
的相应职责，不再添加同功能初稿阶段。Verifier为现有验证角色的改造；自然阅读评审
并入现有Balancer/最终Critic，不单独新增模型裁判或逐变体请求。Balancer具备视觉
输入能力是新路径的明确依赖；配置不支持时明确报不支持，不能静默退回按坐标规则
裁定自然阅读。全部模型工作、纠错、草稿预览和编辑成本有日志、身份和有界账本。

## 三、原始材料、故事与科学保留要求

SourceDocument 是不可变材料包：论文哈希、原始 Markdown、稳定章节/段落ID、
所属层级、chunk索引、可得页面信息、表格文本/原图/图注和公式原文。
保留原始字符与明确的规范化映射；摘录校验可规范化空白，但不能改变语义。
章节重排、表格转换失败、未知页面等状态必须如实记录。

连续章节是写作依据。章节摘要或全局故事只帮助组织，不可替代原文成为事实证据。
遇到长论文不能静默截取前几段。可压紧无关元数据，按章节提供有界材料包；
任何分包模型阅读/核验都必须显式记账，必需上下文无法提供时停止而非猜测。

SourceNarrativePlan 记录研究问题、核心贡献、方法/结果关系、必要条件和来源。
少量 coverage_obligations 只约束“不得丢失的含义及其必要条件”，不是可写事实清单。
它不规定最终句子、模块数量或图表数量，也不把每个科学事实设为必需。
不得为了通过版式检查把先前的必要含义悄悄改成可选。

## 四、15种家族及变体

统一由 FamilyContract/合法 LayoutSpec 提供约束，不写15套独立正文算法。
区域数不等于模块数；capacity是结构上限，不是必须生成的模块数量。

| 家族 | 正文与模块组织适配 |
|---|---|
| classic_three_column | 保持3个 unsplit/unspanned 主区域，各区可叠放多个连贯模块。 |
| asymmetric_two_column | 窄叙事区与宽证据区形成不同解释密度；模块数依赖内容与宽高。 |
| four_column_modular | 4列不是4模块；允许各列承载多个适合窄宽度的模块。 |
| central_hero_side_rails | 主区解释真实核心方法/证据，侧栏组织相关背景、条件或发现。 |
| top_hero_bottom_grid | 顶部遵守真实发现的角色约束，底部组织相关解释，不能假造结论填主区。 |
| horizontal_narrative_bands | 按横带的实际宽高组织阶段性叙事和图文。 |
| method_flow_spine | 中轴必须承载真实方法；程序性顺序需要原文支持。 |
| comparison_split | 按真实比较对象/条件组织分支；布局不能制造原文不存在的比较。 |
| result_dashboard_cards | 卡片围绕实际发现及必要比较口径，主结果区保留真实结果。 |
| small_multiples_matrix | 只对有真实可比关系的实验组织并列模块；不能机械拆碎连续解释。 |
| timeline_stage_narrative | 阶段/时间关系必须由原文支持，几何顺序不是科学时间证据。 |
| modular_editorial_mosaic | 主模块与支撑模块按真实贡献和尺寸安排，不能依照卡片数编内容。 |
| framed_multicolumn | 开场、主体与收束适配跨栏结构，实际阅读路线由模型观察判断；收束承载真实发现/解释。 |
| narrative_evidence_grid | 叙事区说明读者问题，证据网格组织对应实证，收束保留有支持的解释。 |
| central_evidence_band | 上下文与中央证据带相互解释；跨栏、上下区的自然阅读路线由实际预览判断。 |

变体由既有求解器生成，包括契约允许的边界变化、分割、跨栏与镜像。
跨栏以合法区域表示，模块保持唯一归属；模型不直接输出x/y/w/h。
初稿参考候选的区域尺寸范围；Balancer必须改用实际选中候选的尺寸与归属。
不能把默认区域的估计字数当成最终可用空间，不能按模块数平均分配英雄区。

同一家族不同合法变体可采用不同模块数量/边界。也不是任何家族都能容纳任意
模块数：真实容量、必需区域、解释完整性、角色和科学关系仍然有约束；这些约束不产生硬编码
全局模块顺序。没有合适内容
或有限搜索耗尽时正常失败，不用填充、改科学结论或换成固定三列兜底。
不为每个变体调用一遍写作模型；所有变体共享既有有界搜索和样本编辑预算。

## 五、SourceCurator 的写作输入与输出

输入：原章节内容及层级、全局故事与读者问题、科学保留要求、源图表及完整图注、
家族契约、区域尺寸/合法变化范围、字体和画布物理信息。

输出：整份候选正文，动态模块ID/标题、研究功能、主观点与支撑解释、图表选择及
科学用途、阅读/归属意图、来源定位线索。不要求每个来源点对应一条展示句。
可综合跨段材料，解释机制、实验口径与比较结果；可组织主题、主支撑层级或真实步骤。
不得重复照抄摘要、堆变量定义、机械列基线或生成泛化影响模块来凑模块数。
主次结构通过既有渲染可表达的格式输出，避免任意Markdown导致测量/显示不一致。

来源线索至少含原章节/段落ID和相关原文摘录。它们由模型提出、由程序精确检查，
不是已通过的证明；Verifier可使用提供的原章节上下文独立定位支持或发现矛盾。
图注里的成本设置、目标率、指标/单位等必要解释应在可见正文/图注中保留。
不强制图片配额，不引入被撤回的图像语义关联裁判。

## 六、FamilySourceBalancer 的编辑契约

输入：完整当前草稿、原章节、科学保留要求、实际LayoutSpec和模块归属、真实宽高、
图表占用、文字测量、溢出量、区域末尾留白、跨区空洞、实际预览和剩余预算。
先对预览独立判断路线，再评估衔接，不把原文顺序/Curator意图当标准答案。
镜像候选按坐标描述物理左右，不只根据left_rail/right_rail名称给反馈。

动作：有来源地补充机制与条件；改写冗长或摘要式正文；删去冗余可选内容；
在契约内拆分/合并/新增/删除可选模块；按合法关系请求调整模块归属或变体。
整稿作为上下文/输出，但实际只修改诊断涉及的模块，未修改模块保持原样。
不把初稿句子条数/顺序与模块边界设为科学不可变条件。

保护的是必需科学含义、条件、比较口径、解释完整性和原始出处。必要前提可在本模块
自足地说明，不自动转为A模块必须排在B模块前的机器规则。原文顺序作为
来源元数据和默认叙事参考保留，不自动等同于海报必须照搬的线性顺序。展示句、模块ID和
科学保留要求使用不同身份。拆并产生新显示身份，记录旧新对应，既有草稿和
核验记录不可覆盖。候选变换必须能证明没有丢失必要含义或改变局部解释关系。
不能仅以更短、文字更多、空间更满或分数更高判定改稿成功。

所有改稿作为新候选暂存；通过来源/语义检查、实际拟合和内容/空间保护后才采用。
阅读问题按模型诊断在已有轮次内改善；不再以原文顺序或另一个固定阅读规则拒绝。
修改后模型自称“已修复”不等于对新预览做过复查，实际状态由输入指纹决定。
失败回到最近一次完整有效候选，保留失败正文、输入、反馈、原因和消耗。
目标优先考虑缺失解释/严重留白/溢出及公平轮次，不能让摘要相似度永久压过严重空间问题。

## 七、直接原文核验

核验范围：最终可见正文、含科学断言的模块标题/小标签、可见图注，以及正文公式。
不把作者、全局故事、邻居模块的生成文本、旧分数或模型自己的上一次结论当成证据。
原图像素的细字可读性由图表/物理检查处理，不声称RenderFit已核验图片内部文字。

A. 确定性来源预检：来源ID必须存在，摘录必须在对应原文出现，段落、章节、表格
与图注必须正确关联。无效出处不是科学通过。不能用全文中随便一个相同数字支持当前句子。

B. 上下文材料包：提供被引用的完整段落、必要的前后段、所属章节标题，以及相关
表格/图注/公式。作者给出的出处只是线索，核验可从同包原文中独立寻找支持或反例。
来源缺失、存在多个不明指代、表格无法可靠提取时明确不足，不能用模型记忆补充。

C. 同一Verifier按完整模块进行有界核验，并看到全稿解释上下文。在同一次响应中
覆盖每个科学断言及其关系，判断实体/方法、数字与单位/范围、实验条件/总体、
指标与比较对象/方向、因果与不确定性、必要限定和跨句依赖。多段原文可以联合支持
一段综合解释；无需原文逐字一致，也不要求一个句子只包含一个断言。

D. 返回可检查证明：每个候选文本片段对应的支持原文片段及来源位置、明确支持判定、
关系判定、必要信息保留/覆盖判定与具体问题。候选片段覆盖所有可见科学文本；
来源片段回查原文，不能靠一个笼统supported=true或几个相同数字放行。
结构化JSON Schema、raw/parsed/validation日志和缺失布尔值拒绝沿用v9工程原则。
覆盖引用是海报候选文本的切片，不是要求正文照抄论文。

E. 数字与符号辅助检查：在对应支持上下文内检查单位、百分数、区间、正负号和
公式关系。无歧义的表示规范化显式记录；区分level-2这类标识与实测数量。
不能靠把2改成英文、在全文找到相同数值或宽松单位转换绕过语义核验。

F. 结论分类：supported、unsupported/contradicted、insufficient_source、
invalid/incomplete_verdict、request/system_failure分别记录。只有明确支持且完整
的结果才能进入已核验候选。科学拒绝不是格式重试触发条件。

Verifier可诊断或建议修正，但任何建议文字都是未核验草稿；需要编辑后重验，
不能把自我修正直接标记通过。后续补上下文/语义修订属于既有有界工作机会，
不形成免费无限查询。格式纠错仍只用共享的一次准备纠错额度。

一致性和内容覆盖分别报告：必须确保已写内容有支持、必需科学含义未丢失；
不要求把论文的全部事实搬进海报，也不把“用了多少ev条目”当质量指标。
自动语义判定不能承诺100%正确；程序可强制来源真实、核验完整、明确通过和
最终版本一致。真实可靠性必须通过错误案例与实际论文人工核对验证。

## 八、最终冻结与变更重验

循环应是“草稿 -> 物理拟合/必要编辑 -> 来源语义核验 -> 最终拟合 -> 一致候选”。
拟合若删句、换模块或改变局部解释关系，即使某个句子文字未变，也要判断是否使旧核验失效。
文字、条件或解释上下文改变的部分重新核验；仅坐标变化且上下文完全相同可复用科学证明，但不能复用旧图的视觉阅读结论。
视觉阅读报告绑定候选/文本/几何/图像/字体样式指纹；最终Critic判断只对应最终PNG。

冻结绑定论文hash、精确可见文本、模块上下文、来源包hash、Verifier/提示词身份、
核验结果、图表选择、LayoutSpec/几何指纹与预算状态。设计阶段只能做允许的样式与几何。
渲染前重新检查实际可见文本与核验快照一致；样式不得插入新的科学文字。
草稿预览复用真实测量/编译/渲染能力并使用明确的字体/层级，不只用纯框线图冒充成图。
预览与最终样式可能有差异，必须记录；样式变化会使视觉结论过期。
现有标题几何修复可保留，但任何科学标题改写要派生新候选并重验，不能改写冻结正文。

Preflight/RenderFit验证几何与实际可编辑文字，不能替代语义核验。Critic高分也不能
使未通过科学核验的正文合法。最终阅读歧义作为质量问题记录，不恢复旧排序硬门禁，
也不成为隐藏低质量样本的发布过滤器。已完整渲染的低分/质量失败海报继续全分数保存。

## 九、预算、停止与恢复

保持样本最多4次实质编辑，其中capacity/structure最多3次，quality最多1次。
每轮受影响旧模块数<=2且受影响新模块数<=2：因此2并1、1拆2可表达，
但不能借整稿输出修改未计费的其他模块。初稿模块数量不受这个编辑目标上限限制。
图表恢复仍使用独立的既有有限探测预算，不借恢复额外生成正文。
阅读审看和可能的修改包含在同一次既有Balancer调用中；quality审看即使决定不改，
其机会也已消耗。不能因需要复查再额外申请免费quality、每变体阅读请求或新评审代理。
草稿预览数量同样有界，复用已有物理请求限制/去重账本；若现有接口没有覆盖预览，
实现时显式登记有限预览子预算，不扩张模型编辑上限。所有新增耗时/视觉token如实记录。

首轮核验、修改后核验属于明确的验证工作；不为每个断言新增独立模型请求。
按模块有界批次调用同一Verifier，保留各模块结果和最终全稿关系/义务覆盖汇总。
语义修改后的旧证明仅在文字、上下文、来源与身份完全相同时复用。
准备格式纠错仍共享一次；不新增每模块/每句免费重试或第二个语义裁判。

每次调用先记账，保存原始响应、解析结果、源输入和prompt摘要。完成响应可重放；
已收费但缺响应/历史损坏拒绝重发。科学不通过、格式错误、超时/截断和编程错误分开。
force-stop传播到当前安全边界；resume遵守原budget/身份，不退款，不重置变体搜索预算。

## 十、数据与存储

拟采用以下职责明确的数据对象（名称可按实现统一）：
- source_document：不可变原文及原始图表索引；没有evidence_bank。
- source_narrative_plan：每样本研究故事、源顺序和必要含义。
- editorial_candidate：版本化模块、正文层级、来源线索和图表组合。
- layout_feedback：实际变体、测量、草稿预览及诊断，而非估计成功证书。
- reading_review：输入图像/候选指纹、主路线/可接受替代及分组、问题与评审范围/状态。
- source_verification_report：生成后建立的候选文本/原文支持对应和判定。
- verified_body_snapshot：最终正文、上下文和核验身份绑定快照。
- candidate_lineage：本样本内部草稿编辑对应，非跨样本演化/检索。

布局适配层可继续使用稳定的显示item_id/claim_id和text_content，但这些ID仅标识
当前展示表达；不得伪造ev IDs、空证据库或无核验verified=true来通过旧接口。
所有科学真实性判断转向真实source证明。保留每个编辑和核验候选，不覆盖历史。

生成/准备/正文/论文基础身份必须版本化（例如新的generator/preparation版本），
改变身份拒绝旧run resume。阅读策略和相应Critic评估身份也独立升级，
不将旧family_reading_v4的规则分数伪装成新视觉判断。若存储schema需要升级，提供只读旧版解释，不做隐式迁移。

旧缓存当前绑定EvidenceBuilder与抽取设置，不能原样假定兼容。首个新版真实验收默认
建立新版论文基础；只有实现并验证parser-only严格身份与字段白名单复用时，才允许
复制原PDF/解析文本/图表。绝不导入旧evidence或旧样本科学结果作为新样本输入。

## 十二、验收标准

A. 去除限制的真实验收：构造原文明确包含、有用但旧EvidenceBuilder未提取的机制，
   新Curator能够使用它并通过直接原文核验；未提供支持的相似新增解释仍必须拒绝。
   测试Rubrics运行中EvidenceBuilder不被调用，也不要求ev_...或空bank兼容。

B. 科学反例：数字相同但对象错误、比较方向颠倒、单位/区间/负号错误、训练测试总体
   混用、成本设置/目标率丢失、相关变因果、潜力写成已实现、别名指代不明、公式算符
   变化、虚假/错位出处、部分断言支持、缺覆盖、模型返回输入或缺布尔值全部拒绝。
   正常跨段综合、准确改述和无歧义表示规范化必须有正例，避免旧格式误杀重复出现。

C. 动态模块与15家族：逐家族测试契约、合法split/span/mirror、阅读、独立比较分支、
   条件角色与真实图文测量；证明不同论文/有容量差异的合法变体能够形成不同模块组织，
   而非机械规定每家族N。不是要求每个输入在每个家族都生成成功。

D. 视觉阅读：同样内容在列优先、行优先、跨栏/混合路线、镜像、比较分支、矩阵中
   均可合理判断；不以source_order或角色次序当标准答案。模型能识别真实跳读/回跳、
   入口歧义和缺必要解释。测试非法ID/遗漏/重复/错误图像指纹、缺schema字段及
   ambiguous/unassessed状态；只改声明不能改变对真实预览的判断。改稿/换图后旧评审
   过期，quality末轮后不能免费复查，最终Critic针对最终图并保留质量失败结果。

E. 编辑完整性：有界拆并/增删、必需信息保留、旧新ID映射、上下文改变重验、未改邻居
   不被偷改、科学失败不泄露、布局失败回滚和最终可见文本完全匹配。

F. 恢复与历史：预算先收费、缺响应拒绝重发、格式纠错共享额度、停止传播、检查点
   身份拒绝漂移、旧数据只读、缓存字段过滤、原始历史文件前后hash一致。
   standalone classic及共享物理/渲染边界测试必须通过。

G. 真实论文：CPU测试之后，以同论文对照旧v9、上游示例和新版的首稿/改稿/最终正文，
   人工核对原文，检查贡献解释、必要条件、主支撑层级、图表说明和空间安排。
   选具有不同结构的代表家族作真实检验；15家族契约全测不等于15家族审美全成功。
   保存真实PNG/PPTX、正文差异、来源核验和物理检查；不只看分数，不过滤坏样本。
   任何真实运行沿用GPU5、不得干扰GPU3，确认启动后按用户偏好留后台，结束后检查产物。

自动语义核验无法数学保证100%准确；对外明确报告通过、拒绝、不足与未检查。
目标是原文支持真实可查、科学判断完整明确、最终文本与通过版本一致，并通过真实
样本验证正文质量。删除EvidenceBuilder不等于保证更快：新阅读/核验上下文可能更长，
需实际计时与成本记录，不预先承诺质量或性能。


## 十三、自然阅读判断的最终设计（取代上一版硬路线方案）

### 13.1 取消哪些旧行为

实施基线v9执行family_reading_v4；新版Rubrics已按本节改造，classic及历史兼容解释保留。新Rubrics路径取消：
- 以原文章节/证据位置或ROLE_RANK生成必须遵守的模块总排序。
- 按预设家族阅读法认定只有列优先或行优先正确。
- 为满足上述顺序而强制改变区域内堆叠，或执行128-state阅读专用重分配。
- 由旧顺序产生READING_ORDER_UNRESOLVED、NATURAL_READING_ORDER_CONFLICT或
  DECLARED_READING_ORDER_MISMATCH的生成/Preflight硬拒绝。
- Critic将同一套来源/角色逆序计数作为自然阅读质量结论。

保留所有来源位置用于查原文；保持内容角色、真实比较/时间/方法语义与家族几何
合法性。entry_roles/reading_order/sequence hints可以表达作者意图或结构描述，
不能自动证明读者会这样读。科学核验检查必要解释是否可获得、前提是否清楚，
不把它们自动转换成模块坐标先后约束；必要定义可局部重述，真实科学关系不能编造。
物理上限、越界、遮挡、重叠、唯一归属、图文测量、确定性编译仍由程序检查。
共享文件若仍被classic使用，按路径隔离，不直接删除共享实现或改历史解释。

### 13.2 模型看到什么，如何判断

Balancer看到实际候选预览（足够辨识层级/分组/图文），并同时得到准确的模块ID、
标题、完整文字、bbox、分组/跨栏、图表与物理左右。可使用整图加有界局部视图；
局部视图不可替代整图。ID叠层仅用于审计定位，不添加箭头、编号暗示标准路线。
图像不足以判别时明确incomplete，不宣称看清；仅文字/坐标估计不能冒充视觉完成。

第一步独立观察，给出读者最可能采取的路线及可接受替代；第二步沿这些路线检查
内容是否可衔接、条件是否自足、有无被迫跨栏来回、模糊入口或无提示跳跃。
“上到下”和“左到右”是平级习惯，既无全局优先轴，也无家族固定答案。
允许整列读完再换列、逐行跨列、跨栏标题后进入局部分组等混合路线。
比较/矩阵等并行分支允许多个合理次序，不强行给所有模块唯一全局总排列。
完整原文可用于编辑，来源顺序不作为阅读正确答案传入判断标准。

返回同一个结构化Balancer响应内的reading_review：
- candidate_id、image/text/geometry/style指纹与实际观察范围。
- status：clear / needs_revision / ambiguous / incomplete。
- primary_route、acceptable_alternatives与group/branch结构，使用真实模块ID。
- 具体歧义位置、视觉/衔接理由、影响以及建议（调合法位置/层级、补局部条件等）。
- 实际编辑动作；可以报告已清楚且不修改，不强制凑阅读问题。

程序只验证schema、ID存在、覆盖与分支结构合法性、图像/候选绑定、缺项及非预期
重复。共享前言/收束可作为分支汇合节点有意重用，禁止把这种重用误判成复制模块。
程序不另外计算行/列/原文逆序来推翻模型的路线判断。模型评审并不保证每位读者
一致；分歧与不确定如实保留，必要时在验收时人工评阅。

### 13.3 调用、修改、最终评审与失败状态

视觉判断嵌入已有Balancer机会，最多3次capacity/structure加1次quality；只有
存在实际预览的调用可标记视觉评审完成。最后保留的quality机会必须接收当时完整
候选预览并同时做内容与阅读审看，正常无修改也计一次已用机会。请求和渲染都
先记账、保存输入和响应；无法支持视觉输入不能偷偷换回旧规则。

改稿/换变体后旧reading_review只属于旧候选。程序更新状态为待复查，不能采用
模型“这个改法应该更清楚”的预测作为新图审查。若还有既有轮次，可在下一轮观察
新预览；没有额度则明确预冻结视觉未复查，不能追加免费模型调用或冻结后改稿。
阅读问题可触发有界修改，但不是新增的科学/物理失败，也不恢复旧排序拒绝。
新候选能否采用仍需直接原文核验、实际拟合及既有内容/空间保护。

最终既有Critic使用真正交付PNG、完整模块/坐标文本执行独立自然阅读评价，并报告
最终图像指纹、主路线/分支、问题和确定程度。旧预览结论不得代替这一次最终观察。
最终质量差或阅读歧义保留实际结果和报告，遵循全分数存储；不自动追加改稿/重跑，
不通过分数门槛隐藏样本。科学/物理有效性继续决定是否可形成正式海报。

格式不合规按既有共享纠错政策处理；不完整/缺响应不默认为clear。正常评审歧义
是质量信息，系统故障按现有错误分级处理，不将系统故障伪装成评审通过。最终预览、
最终PNG及评审输入若不同，分别留存，避免把不同版本结论混用。
